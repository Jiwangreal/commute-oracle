HappyDriver 通勤先知

明早几点走，今晚就知道；路上有变，提前叫你。基于高德天气、交通态势与路径规划，预测未来 7 天的最佳出发时间与路线，把「上车才开地图」变成「出门前就收到结论」。

形态：单页 Web（移动 / 桌面自适应） 走廊：江宁招商名筑 → 中科曙光 数据：高德开放平台实时接口 Demo：可时间旅行

1选题背景

通勤不是「查路况」，而是一场每天重复发生的、必须在出发前完成的小型决策。

1.1 一个每天都在发生的小型决策灾难

北京早高峰，回龙观到上地 15 公里的路，同一辆车、同一个时间，周一要 42 分钟，周三下雨要 68 分钟，遇到京藏高速事故可能要 95 分钟。绝大多数人的应对方式是：上车、点火、打开地图、看到一片红、然后焦虑。

① 时间上的滞后路况是出发后才看到的，而「几点出门」必须在出发前决定。
② 信息上的割裂天气、路况、限行、地铁故障散落在不同 App，用户要靠心算。
③ 解释上的缺失「预计 58 分钟」里有多少是天气、多少是事故？不知道，就不敢信。
④ 主动性上的空白所有地图产品默认「用户来查」，但通勤是高度规律的重复行为。

1.2 我们想做的事

把「上班路上查地图」提前到前一晚 21:00 和当天早上 07:30，把「看路况」升级为「收结论」：

「明早建议 07:55 出门，比平时早 5 分钟。天元中路百家湖段 07:30–08:50 拥堵概率高，江宁有暴雨，预计 08:57 到公司，把握 72%。」

用户不需要理解模型，只需要知道几点走、为什么、有多确定，以及一个「开始导航」按钮。

高德天气 交通态势 路径规划 v5 URI API amap-gui CLI / Skill

途中

2.3 页面结构

① 晨间播报卡出发时间、与平时的差值、到达时间、风险、把握、三个动作。
② 路线地图JS API 2.0 底图 + 路况图层 + 主/备路线 + 起终点与事故点。
③ 未来 7 天每天一张小卡：推荐出发、耗时、天气、风险；点一天看细节。
④ 为什么把耗时拆成自由流 / 早高峰 / 天气 / 突发四段，附三条证据。
⑤ 演示控制台时间旅行、注入暴雨 / 事故 / 地铁故障，30 秒看完闭环。
⑥ API 日志每条真实请求的接口、耗时、返回摘要，可展开原始 JSON。

2.5 预测模型（可解释的轻量融合）

T_pred(d,t) = T_free × scale × K_time(weekday,t) × K_weather(d) × liveAdj + ΔI(d,t)
因子含义来源
T_free自由流耗时距离 ÷ 城市快速路自由流速度
scale实时校准当前高德实测耗时 ÷（自由流 × 当前历史系数），抑制模型与实测脱节
K_time走廊早高峰曲线星期 × 10 分钟系数表（0.95–2.95），可由真实历史行程回归替换
K_weather天气影响晴 1.00 / 小雨 1.12 / 中雨 1.22 / 大雨 1.35 / 暴雨 1.50 / 雪 1.45 / 雾 1.30
liveAdj实时拥堵校准交通态势的 congested + blocked 比例 → 0.94–1.06
ΔI突发事件事故 +12 分钟起、随时间线性消散；地铁故障 +18 分钟

决策规则：在候选时刻里，选择「到达 ≤ 期望到达」概率 ≥ 80% 的最晚出发时刻（让用户多睡）；若全部不满足，则给出「最早可行出发 + 预计迟到 X 分钟」的诚实结论。

Risk = 0.45 × 时间风险 + 0.30 × 天气风险 + 0.25 × 路况风险   →   0–100 Confidence = 0.92(D0) / 0.86(D1) / 0.79(D2) / 0.72(D3) / 0.60(D4) / 0.56(D5) / 0.52(D6)

可解释：把 T_pred − T_free 拆成四段，用堆叠条呈现；每条建议附「天气 / 路况 / 历史」三条证据，点开可看原始 API 字段。

边界：高德天气预报返回 4 天，第 5–7 天由同季节气候先验 + 趋势外推得到，界面标注「外推」，不伪装成实时预报；事故不宣称可预知，只做发生后的快速响应。

2.6 数据流与降级

7每次刷新并行调用 7 个高德接口
<1.5s首屏数据聚合耗时（实测）
0后端依赖，静态站点即可运行

启动：并行请求两地天气、走廊 3 点交通态势、3 条驾车路线、1 条公交路线 → 预测引擎生成 7 天 × 候选时刻矩阵 → 地图与时间轴联动。

降级：任一接口失败 → 使用 assets/js/snapshot.js（构建期由真实接口生成），顶部显示「快照 + 生成时间」，功能不缺失。

3商业价值

3.1 解决谁的问题

对象痛点价值
通勤族每天在「几点走」上赌运气少迟到、少焦虑、多睡 10 分钟；一年 250 次通勤，每次省 6 分钟就是 25 小时
企业 / 园区恶劣天气大面积迟到、班车调度靠经验错峰上班、班车排班、天气预案；把「明天大面积迟到」变成可提前干预的事件
平台导航是「出发后」的单次工具流量创造「出发前」的高频决策入口与服务分发位（打车、地铁、充电、咖啡自提）

3.2 落地计划

1 个月
参赛 Demo

单城市单走廊 Web；真实数据 + 可解释模型；在线演示与录屏。

3 个月
产品化

接入高德 App 通勤卡片 / 小组件；用历史行程自动学习 K_time；服务端巡航与推送；覆盖 10 条走廊。

6–12 个月
规模化

多城市、多模式（驾车 / 公交 / 骑行组合）；企业版；与天气、交管、地铁运营数据联动。

北极星：周活跃通勤用户 × 建议采纳率 MAE 播报打开率 导航唤起率 提前出门建议准确率

3.3 风险与边界

  • 隐私：家 / 公司地址默认本地存储、不上传；服务端仅存脱敏走廊 ID。
  • 预期管理：预测带置信度，明确标注「外推」「估算」；不承诺 100% 准确。
  • 合规：地图与数据均来自高德开放平台，遵守服务条款；演示 Key 仅用于赛事，正式上线做域名白名单与配额管理。

评分点自检

  • 完成度：真实接口 + 真实地图 + 完整闭环（预测 → 通知 → 路线 → 导航）。
  • 创新性：以「出发时间」为第一输出，而非「路线」；把不可见的天气 / 路况变成可解释的增量。
  • 可用性：一屏结论、3 次点击完成设置、移动端可用、断网可降级。
  • 商业性：C 端高频入口 + B 端通勤 SaaS，落点清晰。
  • 合规性：数据来源清晰、隐私本地化、预测有置信度与免责声明。
